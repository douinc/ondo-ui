ondo-ui는 npm 패키지의 버전 번호를 `MAJOR.MINOR.PATCH` 형태로 관리합니다(`packages/ondo-ui-cli/package.json`). 공개 웹사이트는 private 패키지이며, 직접 작성하는 영문/국문 Changelog는 Changesets가 npm용으로 생성하는 패키지 changelog와 별도로 유지합니다.

## 각 자리의 의미

| 자리  | 언제 올라가는가                 | 예시                                                      |
| ----- | -------------------------------- | --------------------------------------------------------- |
| MAJOR | 브레이킹 변경이 배포될 때        | CLI 스키마 마이그레이션, 여러 컴포넌트에 걸친 구조 변경   |
| MINOR | 기능이 호환되는 방식으로 추가될 때 | 새 컴포넌트, [조합 컴포넌트](/compositions), 유틸리티 추가 |
| PATCH | 수정이나 호환되는 조정이 배포될 때 | 버그 수정, 스타일 조정, 메타데이터 수정                   |

상위 자리가 올라가면 그 아래 자리는 모두 `0`으로 초기화됩니다 — 표준 semver와 동일합니다 (`1.2.3` → MAJOR 변경 → `2.0.0`).

## 릴리스 하나에 한 번의 상승

날짜별 [Changelog](/docs/changelog) 항목 하나는 정확히 하나의 버전 상승에 대응합니다. 한 릴리스에 여러 종류의 변경이 섞여 있다면(예: 새 컴포넌트 추가와 기존 컴포넌트 수정이 함께 나가는 경우), 가장 상위 등급의 자리만 올립니다 — MAJOR > MINOR > PATCH 순으로 우선합니다. 한 항목에 여러 번 버전을 겹쳐 올리지 않습니다.

버전 번호는 항목의 frontmatter에 `version: 0.1.0` 형태로 넣고, 페이지에서 읽기 좋도록 본문 상단에도 `v0.1.0`으로 함께 표기합니다.

Changelog의 순서를 정하는 것은 이 frontmatter 필드입니다. 파일명에는 날짜만 담기는데 같은 날 두 번 릴리스할 수 있고, 그럴 때 어느 쪽이 먼저인지는 버전이 결정합니다.

## 릴리스의 단일 진실 공급원

패키지 릴리스의 기준은 Changesets입니다. 기능 브랜치에서는 `bun run changeset`으로 changeset을 추가합니다. 릴리스 과정에서 `Version Packages` PR이 생성되고, 이 PR이 `packages/ondo-ui-cli/package.json`과 `packages/ondo-ui-cli/CHANGELOG.md`, lockfile을 갱신합니다. 해당 PR을 merge하면 trusted npm publisher를 통해 publish됩니다.

직접 큐레이션하는 영문/국문 웹사이트 Changelog 항목(`content/docs/changelog/`)은 생성되는 npm 패키지 changelog와 분리해서 유지하세요. 이미 배포된 `1.3.1` 패키지 다음의 호환 기능 추가 릴리스는 Ondo CLI 명령 표면을 포함하는 `1.4.0`입니다.
